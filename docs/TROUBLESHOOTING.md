# Resolver problemas durante el taller

Empieza por decir **qué ves, qué cambiaste y qué sí funcionó antes**. Comprueba una causa a la vez. Para corregir conexiones, desconecta USB y cualquier otra fuente; Detener código no corta la alimentación. Si una pieza se calienta, huele o la placa reinicia repetidamente, desconecta y pide revisión al docente.

## Localiza el tramo en dos minutos

1. **¿El taller abre?** Si no, verifica la conexión del computador y la URL del docente desde otra red. Una web pública debe responder también fuera del aula. Si hay página pero las operaciones fallan, revisa el mensaje de la API en Diagnóstico; cargar una portada no prueba el servidor.
2. **¿Hay puerto y programa real?** Usa Chrome/Edge de escritorio por HTTPS, el modelo correcto y USB de datos. Prueba el LED integrado antes de atribuir el problema a los cables del LED externo.
3. **¿Hay raw que responda?** Observa la consola con la sonda quieta y en dos condiciones conocidas. Si no cambia de forma repetible, revisa la conexión física antes de calibrar.
4. **¿Hay porcentaje con referencias propias?** Guardar calibración no reescribe el programa de la placa. Reinstala estación con solo Suelo habilitado y comprueba el estado recibido.
5. **¿Llegó al servidor?** En Mi planta revisa dispositivo, origen Hardware y dos horas recientes. Una curva antigua o una muestra Simulación no demuestra recepción actual.
6. **¿Funcionó la regla?** Guarda mínimo e histéresis y recibe una lectura nueva. Verifica alerta y recuperación; Telegram necesita además entrega confirmada.

Cuando pidas ayuda, comparte el modelo de placa, actividad, mensaje de error y último cambio. **No compartas** contraseña Wi-Fi, token de dispositivo, archivo `config.json` ni token de Telegram.

| --------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| No aparece «Conectar USB» o navegador incompatible  | Chrome/Edge en escritorio, HTTPS o localhost. Firefox/Safari no ofrecen Web Serial equivalente.                                                                                                                                        |
| Selector sin placa                                  | Cable USB de datos; conecta sin BOOTSEL después de instalar UF2. Confirma puerto en el administrador de dispositivos. Algunos clones Nano necesitan driver CH340 del fabricante.                                                       |
| Puerto ocupado / acceso denegado                    | Cierra Thonny, Arduino IDE, monitor serial y otras pestañas. Desconecta USB, espera y vuelve a conectar.                                                                                                                               |
| Pico no responde al raw REPL                        | Selecciona Pico W; confirma MicroPython, no Arduino/CircuitPython. Detén código, reconecta, vuelve a ejecutar LED. Mantener BOOTSEL abre disco, no REPL.                                                                               |
| LED no enciende                                     | USB desconectado: comprueba GP2/pin físico 4, resistor 220 Ω, ánodo/cátodo, GND, filas y canal central de protoboard.                                                                                                                  |
| ADC cambia sin tocar sensor                         | Un cable flotante también produce números. Revisa VCC/GND/señal. No hay detección universal de sensores analógicos.                                                                                                                    |
| `NEEDS_CALIBRATION`                                 | Captura extremos físicos separados. Pico usa 0–65535, Arduino 0–1023. Guarda y vuelve a instalar estación para aplicar referencias.                                                                                                    |
| Capturar 20 muestras desactivado                    | Solo funciona con Pico conectada y sin otra operación. En Uno/Nano ejecuta Suelo, copia raw de la terminal a Seco/Húmedo y guarda manualmente.                                                                                         |
| Calibración deja de imprimir raw                    | La captura de Pico detiene el programa anterior. Vuelve a ejecutar para observar raw o instala estación para aplicar referencias. No es una desconexión del sensor.                                                                    |
| No deja guardar calibración                         | Ambas referencias deben estar dentro del rango y separadas al menos 500 en Pico o 8 en AVR. Repite seco/húmedo a la misma profundidad; una separación menor que el ruido observado no es útil aunque supere ese mínimo.                |
| Seco aparece cercano a 100 %                        | Comprueba si invertiste etiquetas Seco/Húmedo. La dirección del raw puede crecer o disminuir; las etiquetas deben describir las condiciones físicas. Corrige, guarda y reinstala.                                                      |
| `UNVERIFIED` en analógico                           | Señal próxima a 0/3.3 V, saturación o circuito incorrecto. No asumir que el sensor está ausente.                                                                                                                                       |
| DHT `NO_RESPONSE`                                   | Verifica DATA GP15/D4, pull-up, alimentación de la variante y espera ≥2 s. No mojar.                                                                                                                                                   |
| DS18B20 `NO_RESPONSE`                               | GP16/D5, GND común, dos 10 kΩ en paralelo a 3V3, colores reales de la sonda. CRC fallido puede ser contacto o interferencia.                                                                                                           |
| DS18B20 85 °C                                       | Valor inicial posible. El driver solicita conversión y espera; comprueba alimentación y espera la siguiente muestra.                                                                                                                   |
| HC-SR04 sin eco                                     | VCC 5 V, TRIG GP17, ECHO GP18 con divisor, objeto rígido a 2–400 cm. Un objeto lejano/blando también causa timeout.                                                                                                                    |
| PIR «estabilizando»                                 | Espera un minuto después de alimentar. Revisa el jumper y ajuste del módulo; no detecta personas quietas.                                                                                                                              |
| Wi-Fi no conecta                                    | SSID exacto y clave; red 2.4 GHz con DHCP. Pico W no entra en portal cautivo/WPA Enterprise del campus sin una red compatible. Usa un hotspot compatible permitido.                                                                    |
| USB lee, dashboard vacío                            | Vincula la estación con el grupo actual, comprueba token revocado y endpoint `/api/device/ingest`. Para Arduino deja abierta la pestaña; sin USB no existe conexión de red.                                                            |
| Error TLS/certificado                               | Reloj UTC correcto, MicroPython con `CERT_REQUIRED`, CA correspondiente a tu servidor, hostname DNS exacto y cadena completa del servidor. No deshabilites validación.                                                                 |
| Endpoint local falla desde Pico                     | `localhost` no apunta a tu computador. Debe ser un hostname alcanzable por Wi-Fi, con HTTPS y certificado confiable; la Pico usa la CA instalada.                                                                                      |
| Pico lee por USB pero falla Wi-Fi                   | Mantén instalada la estación, USB conectado y la página abierta para usar el puente, si el computador llega a la API. Esto comprueba transmisión mediante USB; deja pendiente el envío autónomo Wi-Fi.                                 |
| Arduino «sin respuesta del bootloader»              | Selecciona Uno, Nano o Nano antiguo; los clones antiguos suelen usar 57600. Revisa cable/driver, pulsa RESET justo al comenzar si no tiene auto-reset.                                                                                 |
| Firma Arduino incorrecta                            | Solo Uno/Nano ATmega328P. Mega, Leonardo, Uno R4 y Nano Every necesitan otros protocolos.                                                                                                                                              |
| Compilador Arduino no disponible                    | Inicia el servicio de compilación documentado; la API informa disponibilidad. No se sustituye C++ por un firmware simulado.                                                                                                            |
| Arduino no se detiene                               | Detener código compila y carga un sketch de reposo; espera a que termine la carga. Si no hay compilador o conexión USB, corta la alimentación. STOP por terminal solo funciona en el programa integrado o sketches que lo implementen. |
| Reinicio mientras instala                           | Reconecta e instala el bundle completo. Si el sistema de archivos está dañado, reinstala UF2 y vuelve a configurar.                                                                                                                    |
| Regla guardada pero no hay alerta                   | Espera una nueva lectura válida del sensor correcto. Revisa origen y unidad: raw no es porcentaje; `NO_RESPONSE`/valor nulo no significan cero. Prueba con referencias conocidas, sin añadir agua cerca de la electrónica.             |
| Alerta no recupera al pasar apenas el mínimo        | La histéresis exige un margen. Con mínimo 30 e histéresis 3, 31 sigue en alarma y una lectura válida de al menos 33 permite recuperar. Comprueba que llegó una muestra nueva.                                                          |
| Telegram no entrega alerta                          | El docente configura token/chat, inicia conversación con el bot y prueba envío. Comprueba estado de entrega; el dashboard conserva alertas aunque falle Telegram.                                                                      |
| Cerraste el navegador pero siguen llegando lecturas | Una Pico W alimentada puede seguir transmitiendo por Wi-Fi. Revoca la credencial desde Configuración y corta alimentación; cerrar la página solo detiene el puente USB.                                                                |

Antes de cada taller prepara diez estaciones, comprueba cables de datos, firmware y red, y usa las dos unidades restantes de cada modelo como repuestos. Prueba conexión/reconexión, LED y la sonda de suelo con una cuenta de grupo. Los sensores resistivos de agua/lluvia se secan al terminar; no dejar energizados en agua durante días. Para modificar cableado desconecta alimentación y mantén la parte electrónica lejos de la maceta mojada.

## Si no hay repuesto o la sala pierde red

Con API accesible, **Mi planta → Practicar sin hardware** permite continuar interpretación y reglas. Usa Suelo 29, 31 y 34 con mínimo 30 e histéresis 3 para comprobar alerta y recuperación. Mantén el rótulo Simulación, desactiva el envío de práctica al terminar y anota qué tramo físico quedó pendiente. Las alertas simuladas no se envían a Telegram como lecturas reales.

Si no hay conexión del computador a la API, continúa con las guías previamente descargadas y la lectura local de la placa que siga funcionando. Registra en papel raw, placa, condición y hora. No supongas que el dashboard guardó lecturas durante el corte: la estación no mantiene una cola histórica para reenviar lo perdido. El docente retoma transmisión cuando vuelve la red.

Al cambiar de placa, **repite la calibración**. No conviertas referencias Pico a AVR dividiendo números: alimentación, ADC y unidad física pueden haber cambiado. Conserva por separado las pruebas reales y las prácticas simuladas en la bitácora.
